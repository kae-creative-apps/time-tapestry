You are the Principal Full-Stack Architect for Time Tapestry (`kae-creative-apps/time-tapestry`).

### 1. Instant Interactive Web Playback & Filler-Word Cut Engine
**Problem:** Waiting for `Dockerfile.worker` Remotion rendering creates a 5-minute bottleneck before users see their story.
**Requirements:**
- Build an interactive, client-side story player component (`src/components/playback/StoryFilmPlayer.tsx`) that plays the raw chapter audio while animating synchronized kinetic typography and audio-reactive visuals.
- Implement an audio-timestamp parser (`src/lib/audio/transcript-cleaner.ts`) that takes word-level timestamps from our transcription output (start/end offsets) and:
  1. Detects dead pauses (> 1.2s) and shortens their playback jumps to ~300ms.
  2. Flags filler words ("um", "uh", repeated stutters) and skips their timestamp ranges using HTML5 `AudioContext` / timeupdate events with seamless micro-crossfades.
- Add an audio-reactive visualizer component using `AnalyserNode` that drives the signature Time Tapestry thread/orb animation smoothly at 60fps on canvas/SVG.
- Keep Remotion rendering intact, but re-route it as an optional asynchronous background task: add a "Download Video (MP4)" button that triggers our existing Railway worker via webhook, emailing the user via Resend when ready.

### 2. Resilient Data Layer & State Management (Replacing Brittle KV Blobs)
**Problem:** `@vercel/kv` stores entire story sessions as unstructured JSON blobs, causing race conditions and making relational queries impossible.
**Requirements:**
- Architect a clean, type-safe data access layer (`src/lib/db/`) with a structured schema for:
  - `stories` (id, user_id, org_id, title, status, created_at)
  - `chapters` (id, story_id, theme_index, title, audio_url, transcript_json, status)
  - `takes` (id, chapter_id, take_number, audio_blob_url, duration, is_selected)
  - `recipients` (id, story_id, name, email, street_address, city, state, zip, phone)
  - `print_orders` (id, recipient_id, lob_job_id, status, tracking_events, expected_delivery)
- Provide a database adapter interface (`src/lib/db/adapter.ts`) with typed CRUD operations and query helpers (e.g., `getStoriesByOrg(orgId)`, `getPostcardStatus(storyId)`).
- Add an atomic update wrapper to prevent concurrent take uploads from overwriting chapter data.

### 4. Bulletproof Mobile Audio Recording & Fail-Safe Recovery
**Problem:** Mobile Safari frequently drops recordings if the phone locks, an incoming call interrupts, or connection drops mid-upload.
**Requirements:**
- Rewrite the recording hook (`src/hooks/useStoryRecorder.ts`):
  - Integrate an IndexedDB fallback cache (using `idb` or raw IndexedDB) that writes raw audio chunks (`MediaRecorder.ondataavailable`) to local storage in real time.
  - Implement a session restoration check on mount: If an unfinalized take exists in IndexedDB, prompt the user: *"We recovered your recording from [time]. Would you like to keep it?"*
  - Add explicit handling for iOS Safari `audioContext.state === 'suspended'` on user tap, along with a live input volume meter so the user visibly verifies their microphone before speaking.
