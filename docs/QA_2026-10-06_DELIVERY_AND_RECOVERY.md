## Fixed in this change

**Futile original-film retries.** A selected source word without verified positive duration is preserved in the transcript cache. Retrying the same film version therefore cannot fix that evidence. Previously the owner was offered retry, including after all three attempts had been consumed.

`films/jobstore.ts` now derives retry eligibility for current original jobs. Known deterministic timing, ambiguous-source, boundary, and cached-evidence failures require an editor check. Three attempted runs require an operator check. These cases are rejected on the server and cannot be accidentally requeued by a retryable flag. `FilmJobView` exposes eligibility and a reason; `AutomaticFilmPanel` hides the futile button and describes the hold. Recoverable failures below the attempt limit retain retry. Original recordings and completed artifacts are unchanged.

This is an honest recovery boundary, not an alignment repair. There is still no new forced-alignment or verified editor-repair workflow in this change. No guessed timestamps, deleted untimed words, or synthetic voice fallback were introduced.

## Operational gap requiring configuration review

**The daily web cron is not sufficient for prompt email or automatic send recovery.** `vercel.json` schedules `/api/collection/jobs` once daily at 09:00 UTC. The handler is protected by `CRON_SECRET`, processes at most three provider attempts per pass, and observes the 23-hour idempotency window. A first transient failure at one daily pass reaches the next pass after that safe window has expired. A daily-only deployment can also delay a newly queued email by almost a day, with larger backlogs taking longer.

The Railway worker already checks delivery every minute alongside long film renders, but only when an email or postal enable flag is configured. The lead's read-only inspection of the online Railway production service on October 6 found the recording/ElevenLabs/KV/public-origin/security variables, but no `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `COLLECTION_EMAIL_ENABLED`, `COLLECTION_DELIVERY_ENABLED`, or Lob variables in the inspected service. Shared variables added OpenAI but did not close these delivery gaps. `GLOO_API_KEY` was also absent, which affects the newly added source-based written moment processing.

The lead could not inspect the relevant Vercel workspace while signed in as `team@foronestudios.com`; the deployment URL retrieved from GitHub returned 404 in that session. Vercel production provider values, actual cron execution, and effective domain routing therefore remain unverified. This report does not claim live email or postal delivery is working. Provider flags and schedules were left unchanged.

The absent Lob settings specifically include `LOB_API_KEY`, `LOB_FROM_ADDRESS_ID`, and `LOB_WEBHOOK_SECRET`. The inspected Railway environment also lacked `CRON_SECRET`, `NEXT_PUBLIC_TURNSTILE_SITE_KEY`, and `TURNSTILE_SECRET_KEY`, which the current print-release readiness checks require. These observations do not establish the configuration in the inaccessible Vercel workspace.
