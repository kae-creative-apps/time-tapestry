# Free pilot protection and storage

New resources require a server-verified Cloudflare Turnstile token on hosted sites. The server checks the response's hostname, action and five-minute validity, then records its use to prevent replay. Website Origin must match NEXT_PUBLIC_APP_URL. Existing owners authenticate with private links before an upload, paid AI request or story change can run. These links remain bearer credentials; share them only with the intended person. They are not individual account logins.

Hosted setup requires NEXT_PUBLIC_APP_URL (HTTPS), NEXT_PUBLIC_TURNSTILE_SITE_KEY, TURNSTILE_SECRET_KEY, KV_REST_API_URL and KV_REST_API_TOKEN. Missing configuration fails closed for new activity. BLOB_READ_WRITE_TOKEN must point to private Blob storage for deployed media. The readiness view reports configuration, not a successful live provider test.

Development bypass is restricted to loopback URLs outside Vercel. Next development mode enables it. A local production preview can explicitly set SECURITY_LOCAL_BYPASS=true. This bypass skips Turnstile, not rate limits or quotas. Tests may additionally set NODE_ENV=test and SECURITY_TEST_BYPASS=true with loopback URLs to isolate existing fixture tests. Hosted requests cannot use this test bypass. Never enable preview flags on a public host.

Rate counters are atomic in KV and serialized under a filesystem lock locally. On Vercel, the trusted forwarded client address is hashed into a bucket. Other hosts ignore client-supplied proxy headers and use a shared conservative bucket until a trusted host adapter is added. SECURITY_HASH_SECRET can provide a separate hashing key. SECURITY_PROVIDER_DAILY_LIMIT sets the shared daily provider-action cap, default 500. This is an action count, not a dollar budget; provider account budgets remain necessary. Individual actions have additional short-window limits in src/lib/security/policy.ts.

Default recording storage is 2 GiB per collection, including originals, generated films and in-flight reservations. COLLECTION_STORAGE_LIMIT_BYTES changes this policy without a code edit; it must be at least 512 MiB. Each file is at most 512 MiB. Reservations are locked before issuing upload tokens, and provider-confirmed actual sizes are checked before finalization. Missing originals remain conservatively counted and do not block reading saved stories. Failed cloud uploads can retain reserved bytes. An operator must reconcile the pending provider upload before releasing a reservation; the pilot never silently drops pending files or grants unlimited retries.

Each saved metadata record also has a configurable 8 MiB allowance, set through COLLECTION_METADATA_LIMIT_BYTES. This covers growth in written answers, transcripts, replies and draft history. Oversized writes are rejected without truncating or replacing existing data; existing reads remain available. Original media uses its separate collection budget.

The 45-minute limit applies to one live voice connection, not the lifetime of a story. There is no automatic draft expiry. Retention depends on configured durable storage and backups. See BACKUP_RUNBOOK.md before inviting external testers. Temporary local files, private Blob objects, and GitHub code backups are different things.

Admin login compares the configured ADMIN_SECRET in constant time and issues a signed, seven-day HttpOnly session cookie. The raw secret is not stored in the cookie. Query-string admin tokens are rejected. Changing ADMIN_SECRET invalidates existing sessions. Missing ADMIN_SECRET disables admin access. Read-only admin routes return no-store/no-referrer responses, remove private link and dispatch payload fields, and stream media after checking collection ownership. Admin audits store only action, resource IDs, timestamp and a session fingerprint. Local audits are daily private NDJSON files in the data directory; cloud audits retain the most recent 10,000 events. Admin access is currently a shared operator role, not named individual access or MFA.

The record store supports a pilot with dozens of collections. Listing and initial usage calculation scan metadata. Terabyte-scale operations require an indexed database, durable job queues, independently tested media backups and retention controls. Adding storage capacity alone does not supply those operations.
